# 문자열 덧셈 계산기

---
## 기능 목록
- [ ] 문자열 입력 기능
  - [ ] 커스텀 구분자 추출하기
    - [ ] ⚠️ 정해진 포맷이 아니라면 예외 발생
    - [ ] ⚠️ 기본 구분자와 중복된다면 예외 발생
- [ ] 정해진 구분자와 양수로 구성된 문자열을 입력 받았는가?
    - [ ] ⚠️ 음수 입력 시 예외 발생
    - [ ] ⚠️ `0` 입력시 예외 발생(예: "0,1")
    - [ ] ⚠️ 커스텀 구분자(문자열 앞 `//`와 `\n`사이 문자)와 기본 구분자(`,`, `:`)를 제외한 문자 입력시 예외 발생
- [ ] 문자열 분리 기능
    - [ ] 정해진 구분자를 기준으로 문자열에서 숫자들 분리
      - [ ] ⚠️ 빈 토큰 발생 시 예외 발생 (예: "1,,3", "1,")
- [ ] 합계 출력 기능
    - [ ] 분리된 숫자들의 합 출력  
,.
## 고민거리
* `0` 혹은 빈 문자열(`""`)의 경우 어떻게 처리해야할까?
    - 기능 요구 사항의 반환 예시에서 빈 문자열에 대해 `0`을 반환한다.
    - 빈 문자열을 허용한다면 `"1,,2"`은 사실상 `1`,`0`,`3` 과 같은 형태가 된다.
        - 하지만 문제의 입출력 요구 사항에서 입력을 `구분자와 양수로 구성된 문자열`로 지정했다.
        - `0` 혹은 빈 문자열(`""`)을 허용하지 않고 `빈 입력("")`에 대해서 `0`을 출력하도록 하는게 모든 요구 사항을 충족할 수 있다.

### 구분자 관련
* 공백 문자도 커스텀 구분자가 될 수 있을까?
    - 공백 문자가 커스텀 구분자가 될 수 있다면 `trim()`과 같은 공백 제거 메서드 사용에 주의를 헤야할 것이다.


* 숫자에 대한 검증은 어디서 진행하는게 좋을까?
  - 문자열 입력을 받을 때 진행하면 좋겠지만 `-`을 커스텀 구분자로 사용하는 등의 상황에서 제대로 작동하지 않을 수 있고 로직이 어려워질 수 있다.
  - 숫자 배열 생성 시에 진행하면 로직이 간단해진다.


* 기본 구분자를 커스텀 구분자로 지정한 경우?
  - 기능 요구 사항에 기본 구분자는 커스텀 구분자 외에 지정할 수 언급 되어있다.


* 커스텀 구분자 분류 시점은 어디가 적절할까?
  - 커스텀 구분자는 먼저 처리하는게 이후 분기를 나누기 쉽다고 판단했다.



## 실행 결과 예시

```java
덧셈할 문자열을 입력해 주세요.
1,2:3
결과 : 6
```
